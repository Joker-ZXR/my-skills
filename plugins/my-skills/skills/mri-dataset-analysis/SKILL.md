# MRI 数据集分析

用简体中文报告，代码保持精简。完成实际处理、验证与保存，不仅提供方案。不要修改原始影像、掩膜和 CSV。

## 输入与范围

接收数据集名称、部位、源数据目录、分析范围和元数据输出目录；仅需转换时才需要 NIfTI 输出目录。**源数据目录不要求是 DICOM 路径**，可为 DICOM 目录、已有 NIfTI（`.nii`/`.nii.gz`）目录，或同时包含影像、sidecar、表格和标注的数据集根目录。按实际内容识别格式，不要求目录命名为 `ori` 或 `dicom`。

- 仅有 NIfTI：直接分析，结合已有 sidecar、梯度文件和表格补充信息；不要求提供 DICOM，不重复转换。无法可靠补充的采集参数按规范记缺失，不从 NIfTI 几何信息猜测。
- 仅有 DICOM：需要 NIfTI 时按转换规范批处理。
- 混合目录：匹配源 DICOM 与已有 NIfTI，复用可验证且完整的结果，仅转换尚需转换的部分，避免重复计数。

可从明确路径推导名称和部位。输出目录未指定时，转换结果默认放数据集目录下的 `nifti`，元数据默认放源数据目录下的 `meta_data`；先说明实际采用的路径。扫描时排除本次输出目录（复用的已有影像除外），避免将生成文件重新纳入输入。存在多个合理源目录或会覆盖无关结果时先澄清。

**仅纳入常规 MRI 和 DWI，排除 ADC、FA、MD、RD、AD、T1/T2/T2*/R2* mapping、PDFF 等定量参数图。** 排除定量图不等于排除 T1/T2 加权影像或含扩散编码的 DWI；DWI 本身仍保留 b 值。依据 DICOM/sidecar、发布说明及目录联合判定，不能仅对短名称如 `AD` 做子串匹配。Trace/方向平均 DWI 可纳入但不伪造方向；默认排除计算合成 DWI、定位像和非 MRI。不能确定的记录标为待判定并报告，不静默纳入。用户明确修改范围时按当前指令执行。

## 执行

1. 读取 [元数据规范](references/schema.md)。该规范决定字段和类型；ATLAS 示例仅参考结构，不复制其参数。检查 CSV、Excel、标签说明、DICOM/NIfTI、sidecar、掩膜、划分及重复来源。逐影像收集厂商、扫描仪型号和场强，按元数据规范匹配 DICOM/sidecar/表格中的设备字段；缺失时查可靠发布资料，不从厂商或场强推测型号。
2. 若存在 DICOM，读取 [转换规范](references/dicom.md)。已有可验证对应且完整的转换结果可复用，同时读取原 DICOM 补充元数据；需要转换时直接编写或复用批处理脚本并运行，完成全部待转换序列，不停留在提供脚本或命令。目录遍历、序列分组、转换、头信息提取与逐项验证由脚本循环完成，不由 Agent 逐患者、逐序列或逐文件反复调用工具。先批量清点，必要时只检查少量代表样本；运行时读取汇总进度和错误摘要，不把完整文件列表、正常记录或头信息灌入上下文。失败集中记录，共性问题修复后仅重跑受影响项；持续失败则列明原因，不无限重试。
3. 在 `<当前项目根目录>/pre_processing/data_pre/<REGION>/<DATASET_NAME>/` 保存 `analyze_metadata.py`，必要时保存 `convert_dicom_to_nifti.py`。脚本用命令行指定源和输出，优先复用项目已有实现。保存能重新生成统计和标准 JSON 的分析逻辑。
4. 按可靠 ID 匹配人口学，明确患者/检查/序列/体积/切片/掩膜计数。保留多次检查对应的年龄；患者总体年龄默认取最早可确认检查的年龄，日期无法排序且年龄不同时报告患者年龄无法唯一确定，不任取一条。不同队列同名 ID 不默认合并。
5. 本地缺失信息再查官方发布、仓库和数据论文，保留链接、来源层级与适用范围。逐例来源冲突记录原值，无依据判断时填缺失。文献总体年龄或“主要/95%”协议不能代填个人。明确适用全部纳入影像的协议可填，来源仍标文献而非实测。
6. 默认只输出 `<DATASET_NAME>_meta.json` 和 `<DATASET_NAME>_summary.md`，不再生成 `<DATASET_NAME>_details.json`。**JSON 首个顶层字段固定为独立的 `LabelDefinitions`，用英文统一说明分类标签的编码与含义、分割标签的体素值与解剖结构或病灶名称；其后保留逐影像路径对象，不把这份标签字典重复写入每个 `.nii.gz` 对象。** 数据集级字典描述实际持有的标签及适用范围；逐影像 `TaskType` 只填该影像实际具有对应标签的任务，无标签时为 `[]`。更新既有元数据时同步修改生成脚本与 Markdown，检查字典位于首位，并保留不受本次变更影响的逐影像字段。只记录有来源依据的编码，分割值以实际交付标签为准；未提供、不适用或未知时明确状态，不编造编号，也不把健康描述、序列类别或 Train/Test 当作分类真值。结构与多套编码的处理见 [元数据规范](references/schema.md)。其余统计汇总、来源说明、匹配方法和重要异常写入 Markdown。DICOM 原始头信息、sidecar 和转换清单按转换规范另保留。所有交付 JSON 的数组（含嵌套数组）单行显示，对象仍逐字段缩进；使用 `scripts/format_json.py <文件.json>` 格式化，或在分析脚本采用同等序列化方法，不用正则改写 JSON。
7. 运行 `python3 <本技能目录>/scripts/validate_metadata.py <meta.json> --require-label-definitions`。它只检查结构，不替代影像数、路径、CSV 匹配、梯度对应及空间验证；实测分割标签值必须被对应标签字典覆盖。核对保存结果并清理无用临时文件；不删除本次交付脚本。失败对象列明原因，标记部分完成，不能报告全部成功。

## 报告与溯源

Markdown 用表格给出：范围和排除项；分队列/模态/划分的患者、影像、掩膜、切片数量；配对与患者去重；年龄有效/缺失数、均值±样本 SD(ddof=1)、中位数、四分位数、范围、年龄段；性别人数/比例/编码；疾病及分级；矩阵频数、间距、厂商×扫描仪型号×场强分布及协议参数；设备字段有效/缺失数与其他字段覆盖率；DWI b 值分布和方向完整性；文献补充与本地差异。比例说明分母，四分位数说明方法，4D 切片统计区别空间层数与跨体积累加数。健康无分级记不适用，影像分级不当作病理分期。

`TR_ms-TE_ms-TI_ms-FA_degree` 的字段覆盖率按“至少一项有有效数值”统计，只有四项全缺失才计为整组缺失；另列 TR、TE、TI、FA 各自的有效/缺失数。不把四项齐全率当成字段覆盖率，详见 [元数据规范](references/schema.md)。

**成像信息缺失须定位到具体序列，不能只给总体缺失数。** 从最终JSON生成“序列 × 缺失字段”汇总，保留vendor、高b值等有意义的序列版本；列出缺失字段、受影响影像数/该序列适用记录数及比例、涉及患者/检查数，明确是整类序列缺失还是部分病例缺失。分别说明来源未提供、提取失败、已确认不适用，以及用户纳入派生图时未继承采集参数等原因；不能仅凭NaN/Unknown判定不适用。TR/TE/TI/FA整组缺失与单项缺失分开，b值、梯度及采集类别等未知项也列明涉及序列。文献协议补充及推断关联不算缺失，但须保留来源级别。同步维护生成脚本，核对汇总与JSON一致；部分缺失用少量代表ID或现有清单追溯，不默认新增逐病例文件。

Markdown 的“方法与溯源”部分简要说明规范版本 `1.3`、影像根目录、字段来源/换算方法、患者匹配及去重方法、文献依据及标签编码来源。参数变化、DWI 信息缺失、跨表冲突、跨模态划分冲突、转换和掩膜检查仅给出数量、分布及关键结论；必要时列少量可定位的代表性异常，完整转换错误引用已有清单。健康状态依据实际队列/病例，任务由实际下载并匹配的标签确定，不能仅根据公开用途或未下载的标注填写；汇总实际标注覆盖情况。

**取消 details.json，不把其内容原封不动搬到 Markdown。** 不展开逐病例映射、逐帧参数、全部临床原值、完整审计日志或所有正常记录，也不为替代 details.json 默认新增明细 CSV/TSV。报告侧重统计表和总结；需要追溯时链接现有 CSV、sidecar、dicom_headers.json、conversion_manifest.json 及可复现分析脚本。历史 details.json 不自动删除，仅在用户要求迁移已有结果时处理。

核对计划范围内成功、失败、排除、待判定对象数量，注明计数单位；不将 DICOM 实例与 NIfTI 数直接比较。说明验证是头信息检查、全数据读取还是视觉检查。若转换，附脚本路径、可复现命令及失败清单。末尾简要提供输出链接、核心统计和重要差异。
