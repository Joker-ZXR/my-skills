# 统一 MRI NIfTI 归档

每个新的数据集或整理范围都先给出可核对的完整预案。即使本次请求写了“整理”“执行”，也不能把它当作对尚未展示的目录预案的确认。用户明确认可本次预案后，才执行对应的文件操作；此前已确认的同一预案无需重复确认。用户提出修改意见时只修订预案，直到得到明确认可。面向用户用简体中文，代码保持精简。

## 目标与边界

- 统一保存的是已有 `.nii`/`.nii.gz` 影像及其 NIfTI 标签。必要的 DWI `.bval`/`.bvec` 和已有 sidecar 随对应影像保留。不要为完成本技能启动 DICOM/H5 转换或重做预处理。
- 从项目规定的来源和现有文件核实本次选入的 NIfTI。`base` 保存选定的来源文件，按项目已有的 `anat`、`dwi`、`swi`、`mask`、`label` 等内容类型组织；`mask` 是身体/前景范围掩膜（如 brain mask），`label` 是组织/病灶等分割标签，二值标签也按用途归 `label`。来源已做重采样、去颅骨或归一化的文件仍可作为本次选定输入放在 `base`，在清单注明已有处理状态，不声称它是扫描仪原始数据。处理状态通常不扩展文件名；仅在需要区分同序列的多个处理版本或项目已有此约定时加入短后缀。
- 源文件不覆盖。目录结构由本次预案决定；[目录与清单规范](references/schema.md) 提供字段与候选结构，不能代替用户对具体目录的确认。同一文件只入库一次，fold、训练框架和任务专用目录从冻结清单导出。
- `derivatives` 只保存本次规范归档之后新执行的方向调整、重采样、强度归一化、分割等处理结果；没有新处理就不创建该目录。归档阶段保留影像值、维度、dtype 和物理空间信息，不无依据地把 qform/sform 改成相同矩阵。

## 先沿用现有归档约定

- 命名与层级优先级：用户本次明确要求 > 项目明确约定 > 同一目标库中已完成且可比的归档 > 本技能候选结构。目标目录为空不代表应重新设计命名。
- 提交预案前，检查同一目标库中与本次模态、标签和随访结构相近的已完成数据集，读取实际目录、文件名及当前清单；脚本可能早于后续整理，不能只读旧脚本。预案注明采用的参考库并给出真实路径示例。已有归档有差异时选最相近的约定并说明选择，不把任一旧库的特例强加到所有数据集。
- 沿用已有的类别目录、患者 ID 格式、检查层级、文件名前缀和模态后缀。已有独立 `swi/` 就沿用，不并入 `anat/`。保留当前库文件名中的患者/检查标识，不自行换成无身份短文件名或 `_seq-`、`_acq-`、`_src-preproc` 等新风格。
- 来源序列名、SWAN 等实现名称、已有预处理和未知 b 值记入清单。仅为避免同次检查同模态重名，按现有风格添加必要的短区别，如 `DWI_vendor`、`DWI_b4000`；未知 b 值不能改写为 b1000。

## 第一阶段：只读清点与预案

1. 只读检查适用的项目级 `AGENTS.md`、当前实验方案、来源目录、已有元数据和旧归档。以当前文件为准清点患者、检查、每类 NIfTI、标签、sidecar、处理版本和异常，不用旧盘点数量代替实查。
2. 给出一份具体预案，至少包含：来源和目标根目录；完整的预期目录树及每类文件的真实命名示例；逐类精确纳入/排除数量；`base` 的内容类别和未来 `derivatives` 的边界；源→目标路径与操作的完整映射规则及全部例外；清单字段；患者划分、配对和 QC 的处理；现有目标文件和旧版本如何处置。文件很多时，用能推导任一文件去向的确定性规则、精确数量和例外清单代替逐行铺满答复；规则无法覆盖的文件须逐一列出。没有可沿用的归档约定时，才采用 `base/<类别>/sub-<id>/` 候选结构。不额外增加重复的数据集目录；既有患者 ID 自带的数据集前缀按项目约定保留。无真实多次检查时不强加 `ses-01`。不凭目录名推断处理版本，例如位于 `dwi_norm/` 的原样复制参数图不应标成“已归一化”。用户要求归档的范围与实验训练准入分别记录，不能因为尚未纳入训练而擅自从归档中剔除。
3. 预案阶段仅做只读检查和在答复中展示映射，不创建目标目录、迁移脚本或正式清单，不复制、移动、重命名、删除任何数据文件。明确请用户核对预案；用户指出问题后更新预案，再等待确认。

## 第二阶段：按已确认预案执行

1. 核对来源与已确认预案是否一致。若目录、范围、文件数量、命名或旧版本处置发生实质变化，先提交修订预案并等待再次确认。为每库确定稳定的患者/检查/序列身份，检查重名和目标冲突，保留原患者 ID、原文件名、原相对路径及来源根目录。
2. 仅执行已确认的复制、无损压缩或旧版本处置；保存可重跑的简洁批处理脚本和参数。先检查目标冲突，已有目标等价则复用，不同则报冲突而不覆盖。写入临时目标并校验后再提交；全部目标验证后，原子发布版本化的 `subjects.tsv`、`images.tsv`、`pairs.tsv`。未验证落盘的影像不得标为已入库。
3. 患者级 split 优先读取已冻结名单；仅做归档时记 `unassigned`。配对资格单独记录，不因同人或同 shape 就认定已配准。校验路径、计数、哈希或无损转换等价、体素可读性、几何信息、影像与标签网格和标签值；可疑记录保留来源映射并标记 `hold`。若纳入 4D DWI，核对梯度数与体积数。
4. 报告成功、跳过、冲突、`hold` 的数量、正式目录、清单版本和未完成项。

可采用 BIDS 风格字段，但具体层级由用户确认的预案决定，不自动宣称完整 BIDS 兼容。`imagesTr/labelsTr` 是训练框架导出格式，不作为通用主库。
